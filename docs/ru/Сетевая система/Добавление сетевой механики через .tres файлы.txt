Формат пакета на проводе
text

┌──────────────────── ЗАГОЛОВОК (8 байт) ────────────────────┐
│ [ 2B type ][ 2B body_len ][ 2B fragment_id ][ 2B total ]   │

Шаг 5: Использовать в коде
gdscript

# ═══ Отправка (в скрипте механики) ═══

func shoot() -> void:
	# Локальная логика
	_create_bullet(origin, direction)

	# Сеть — одна строка
	_nam.send_action("shoot", [origin, direction, weapon_id])
	#                          ↑ порядок = порядок полей в .tres


# ═══ Приём (подписка в _ready) ═══

func _ready() -> void:
	_nam.on_action("shoot", _on_remote_shoot)

func _on_remote_shoot(peer_id: int, data: Dictionary) -> void:
	_create_bullet(data["origin"], data["direction"])
	#              ↑ ключи = field_name из .tres


# ═══ Валидация на сервере ═══

func _ready() -> void:   # server_main.gd
	_nam.on_validate("shoot", _validate_shoot)

func _validate_shoot(peer_id: int, data: Dictionary) -> bool:
	if not _pm.has_player(peer_id):
		return false
	var player_pos: Vector3 = _pm.get_player_data(peer_id)["position"]
	if player_pos.distance_to(data["origin"]) > 5.0:
		return false
	return true
Справочник настроек
Sync Mode
text

CLIENT_TO_SERVER          Клиент → сервер. Не пересылается.
						  Пример: запрос инвентаря

SERVER_TO_ALL             Сервер → всем клиентам.
						  Пример: смена времени суток

SERVER_TO_OTHERS          Сервер → всем кроме отправителя.
						  Пример: редко используется

CLIENT_TO_ALL_VIA_SERVER  Клиент → сервер → остальным.
						  САМЫЙ ЧАСТЫЙ. Стрельба, чат, движение.
						  Отправитель применяет локально сам.

SERVER_TO_OWNER           Сервер → только отправителю.
						  Пример: результат крафта, ответ на запрос
Channel
text

RELIABLE      Гарантированная доставка, порядок сохраняется.
			  Стрельба, размещение блока, чат.

UNRELIABLE    Без гарантий, самый быстрый.
			  Позиция игрока (отправляется 20 раз/сек).
Типы полей (FieldType)
text

BOOL            true / false                      1 байт
INT             целое число                       1/2/4 байта
FLOAT           дробное число                     2/4 байта
VECTOR2         два компонента (x, y)             2×(2/4) байта
VECTOR3         три компонента (x, y, z)          3×(2/4) байта
STRING          UTF-8 строка                      2 + N байт
PACKED_BYTES    произвольные данные                4 + N байт
Размер (ByteSize)
text

AUTO      По умолчанию: BOOL→1, INT→4, FLOAT→4
BITS_8    1 байт.  INT: 0-255.  Пример: weapon_id, slot_index
BITS_16   2 байта. INT: 0-65535. FLOAT: half-float. Пример: peer_id
BITS_32   4 байта. INT: полный. FLOAT: float32. Пример: позиция
Квантизация
text

Вместо float → целое число в диапазоне [min, max].

use_quantization: ✓
quantize_min:     -3.15
quantize_max:      3.15
byte_size:        BITS_16      ← 65535 градаций

Пример: угол поворота [-π, +π] → 2 байта, точность ~0.0001 рад

ВАЖНО: значения за пределами [min, max] обрезаются (clamp)!
ВАЖНО: quantize_max ДОЛЖЕН быть > quantize_min!

Предупреждение по half-float (BITS_16 для FLOAT/VECTOR без квантизации):

text

┌──────────────┬──────────────┐
│ Значение     │ Погрешность  │
├──────────────┼──────────────┤
│ 10.0         │ ~0.01        │
│ 100.0        │ ~0.1         │
│ 500.0        │ ~0.5         │
│ 1000.0       │ ~1.0         │
│ 2048+        │ ~2.0+        │
└──────────────┴──────────────┘

ВЫВОД: позицию в мире ВСЕГДА через BITS_32!
	   Half-float только для направлений и нормализованных значений.

❌ Packet Name с пробелами
✅ Только латиница, цифры, подчёркивание: snake_case
Потоки данных
Клиент → Сервер → Другие клиенты (CLIENT_TO_ALL_VIA_SERVER)
text

Клиент A                      Сервер                     Клиент B
────────                      ──────                     ────────

send_action("shoot",
  [origin, dir, wpn_id])
		│
		│ write_shoot() → байты
		▼
   ────ENet────▶  _on_packet()
				  read_shoot() → data
				  │
				  │ data["peer_id"] = peer_id  ← ПЕРЕЗАПИСЬ
				  │
				  │ _validate_shoot()
				  │   └─ return true/false
				  │
				  │ _on_shoot()  ← локальный обработчик
				  │
				  │ field_names → values
				  │ write_shoot(values) → байты
				  │
				  │ broadcast_except(peer_id_A)
				  ▼
			 ────ENet────▶  _on_packet()
							read_shoot() → data
							│
							│ _on_remote_shoot(peer_id, data)
							▼
						 Пуля появляется на экране B

_nam.send_action_to(peer_id: int, name: String, args: Array) -> void

Безопасность
text

┌──────────────────────────────────────────────────────────────┐
│ ПРАВИЛО: Сервер НИКОГДА не доверяет данным от клиента.       │
│                                                              │
│ 1. Поле "peer_id" в теле пакета АВТОМАТИЧЕСКИ               │
│    перезаписывается на реальный ENet peer_id.                │
│    Клиент НЕ МОЖЕТ подделать свой ID.                        │
│                                                              │
│ 2. Валидатор (on_validate) проверяет данные ДО обработки     │
│    и ДО маршрутизации. Если вернёт false — пакет             │
│    отбрасывается, другие клиенты его НЕ получат.             │
│                                                              │
│ 3. Проверяйте:                                               │
│    - Существует ли игрок (_pm.has_player)                     │
│    - Дистанцию (антителепорт)                                │
│    - Cooldown (антиспам)                                     │
│    - Границы значений                                        │
└──────────────────────────────────────────────────────────────┘
